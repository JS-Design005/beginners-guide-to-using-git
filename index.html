Welcome to Git!

What is Git?

What comes to mind when you hear the term version control? Is it backing up your code occasionally? Accumulating hundreds of copies of your project on your desktop? Mine used to be a "back ups" folder with many copies of the whole project organised in carefully labeled folders like; project_v1, project_v2..

While it does work, it takes up so much space! So here is a better idea; imagine having all your backups compressed into one small file inside your main project folder.

That, is excatly what Git is used for! You are able to save "snapshots" of your work making it easy to go back to previous versions. You can even name the snapshots to make them easier to find.

If you want to know how to install or set up Git, or want to know some useful commands, this page has you covered!

GitHub

Common misconception, but Git and GitHub are not the same thing! Git is a locaL version control software used by developers to keep track of their code and save "snapshots" of their work. This is offline. GitHub, on the other hand, is online, and gives you the ability to collaborate with others.

Picture it like this; if Git is the "text editor" on your computer that allows you to save versions of a document, GitHub is more like "Google Docs", storing your file online so a whole team can view and collaborate on a project.


If you have a GitHub account, I recomend using the roreply email address for setting up your Git (explained in more detail later!). You can find it when you change your email settings to private. This will keep your email hidden if you decide to push your projects to GitHub in the future.

Quickstart Guide

1. Download

First, you need to download a copy of Git from Git's official website. Visit Git's website and download the installer. Make sure you select the correct installer for your computer, whether it is Apple, Windows or Linux.

2. Install

Find the installer in your downloads folder. Open and follow the instructions. There are a lot of settings, but don't worry because most of the defult settings are perfect for beginners!

If you use Visual Studio Code, there will be a setting to config an app for git. Choose Visual Studio Code because this will make things easier.

3. Test

Then you test whether the installation worked. Open your command prompt, and type this command: git --version . Press enter. And it should show you the version number for the software.

4. User Settings

For Git to work, it needs to know who you are! So we need to give it a name and an email address.

To set your username, open your command prompt or terminal, and type in the following command and press enter: git config --global user.name "Your name here" .

To set your email, type the following command in the terminal and press enter: git config --global user.email "youremail@here.com" .

Pro Tip!

If you have a GitHub account and plan to push your projects to GitHub, don't use your personal email address.

Instead, go to your Github email account settings and set your personal email to private. Then, look for a long noreply email address that GitHub provides.

We do this to protect your email from the spam bots that are on GitHub. But if you don't plan to put these projects on GitHub, feel free to use your email.

To test if the username and email were successfully updated, we type this command to see the list of settings (your username and email will be at the bottom!): git config --list .

5. Visual Studio

Now you are ready to go! If you use Visual Studio Code like I do, it is really easy to learn how to stage and commit your work! You can use the GUI or the built in terminal. If you have it open, restart it by closing it. Then it will find git automatically and it will be ready to use!

How to use Git

Introduction

Now we will learn how to use git! But please note, this guide assumes you are confident with basic HTML, CSS and are familiar with Visual Studio Code.

1. Repository

First, we need to set your file up as a repository. This will create a special .git file in your project folder. This is where the "bookmarks" or "warp gates" will be saved. To keep things very beginner friendly, lets use Visual Studio Code.

Open a new project folder (it should be empty) in Visual studio code. Then, find the little icon that looks like strings and circles. It should be near the top left hand side of the screen. This is called your Source Control tab.

In the source control tab, you will find a button that says initialize Repository. Click that button, and you will have your first repository!

Now, when you look towards the bottom left of the screen, it should say "main" or "master".

2. Terminal

We use the terminal to write git commands. To open the terminal in Visual Studio Code, we use this keyboard shortcut: Ctrl + ` .

3. Create some files!

Now, we are ready to create a project! We will start with an index.html and a styles.css. Then, we will add a simple boilerplate to the html file, with a heading and a couple of paragraphs.

For the CSS, add some simple styling to your simple web page. It could be a background colour and style the fonts of your heading and paragraphs. It doesn't have to be a lot of code. Now, you are ready for your first stage!

4. Stage

Our project is ready for staging! But before we get to the how, let's brush on the why.

Say you wanted to document your progress for a series of drawings you were working on. You have 5 drawings so far, and they are all at different stages of their progress. Lets just say you want to photograph 3 of them because the other 2 are not ready yet. You "stage" them, by placing them on a seperate table by themselves. And snap a photo of them; leaving the other 2 out. This is what we can do with our code!

You might not want to commit all of your files at once, so this is why we have this "stage" step. Now, if you go to your source control tab, you will see your files there. Hover over them, and you will find a plus button. If you want to select the files individually, you can by clicking on those plus symbols.

To add them all at once, we press the plus symbol on the changes tab, which should be just above those files we looked at before. Congradulations, you made your first stage!

5. Commit

This is the part where we create our first "bookmark"! Near the Commit button towards the top, you will see a Message text bar. Type the name of your bookmark here. For example, we could put, "started the navigation panel". In this case, you could even put, "my first commit!"

Finally, press Commit. Well done, you made your first commit!

6. Tag

So, now that we know how to stage and commit, I encourage you to add a few more things to your little project. Maybe a photo, or some more paragraphs.

Because then, we will make our first tag! Tags are sort of like special bookmarks that say, "hey, an important part of the work is done!". It could be used when the mobile version of a website is complete of when all the updates of a website have been complete and it is ready to be published or shown to the client.

Pro Tip!

The commit is the snapshot, so we can use many of these. But the tag is the permanent label of a version of your project that you are proud of!

We used the GUI for the commits. So lets have a look at our terminal! You can also do your stages and commit in the terminal as well.

So, if you haven't already, open your terminal with this keyboard shortcut: Ctrl + ` .

The terminal can be a little intimidating at first, but rest assured! Click inside the terminal and press enter to clear it.

Now, type this code into your terminal: git tag -a v1.0 -m "My First Git Tag!"

Unless there is an error message (which might just be a typo in your code!), congrats! You just created your first tag!

Git Commands

Terminal vs GUI

While the Graphic User Interface is easier to visualise, it is hightly recommended that you learn to use the terminal as well. This will help you build your professional skills.

Cheatsheet

Common Commands
Command Use
git init Turns a project folder into a repository.
git status Shows what has been changed.
git add Stages, or prepares files for the snapshot.
git commit Commits the change, or saves a snapshot.
git log Shows the history of all your changes.
git tag Creates a big milestone or version.

Git Tree

When you have completed a project, you might want to see a visual representation of all your changes. You can do this with the git tree!

To see your git tree, we will use a long comand. I will explain the comands in more detail bellow. Here is the command: git log --graph --oneline --decorate --all.

It might look a little intimidating, so lets breakit down:

  • --graph: This draws the ASCII "tree".
  • --oneline: Squishes your commits onto one neat line.
  • --decorate: Shows your tags!.
  • --all: Shows everything like your branches.
